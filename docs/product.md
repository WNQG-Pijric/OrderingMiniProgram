## 1. 产品概述

本项目是一个微信点餐小程序，面向个人或小范围使用场景（约 5~10 人）。用户可以通过微信小程序浏览菜品、选择规格、加入购物车、下单并使用虚拟货币支付；管理员与用户使用同一个小程序，通过权限隔离展示不同界面，负责维护菜品、处理订单、赠送余额、发布公告，并与用户按订单进行文字聊天和实时沟通。

核心价值：

- 用户无需排队或口头沟通即可完成点餐、支付和订单追踪。
- 管理员可以集中管理菜品、订单、用户余额和公告。
- 用户与管理员可以围绕具体订单进行沟通，减少信息遗漏。

## 2. 用户角色

| 角色 | 说明 | 主要能力 |
|---|---|---|
| 普通用户 | 微信小程序使用者 | 登录、浏览菜品、选规格、购物车、下单、虚拟货币支付、查看订单、接收通知、按订单聊天、查看首页公告 |
| 管理员 | 同一小程序内的运营与内容维护者 | 登录、管理菜品和规格、处理订单、赠送余额、发布公告、接收微信订阅消息通知、按订单聊天 |

## 3. 信息架构

### 3.1 小程序端

小程序登录后按角色权限渲染不同界面：

普通用户底部包含 4 个 Tab：

| Tab | 页面 | 核心内容 |
|---|---|---|
| 点菜 | 首页 / 菜品列表 / 菜品详情 | 分类、菜品、规格选择、首页顶部公告、加入购物车 |
| 购物车 | 购物车 | 已选菜品、数量调整、规格修改、合计金额、去结算 |
| 聊天 | 会话列表 / 聊天详情 | 用户与管理员围绕订单进行文字实时沟通 |
| 我的 | 个人中心 | 用户信息、我的订单、钱包余额与流水、设置 |

管理员登录后展示管理员界面，包含订单、菜单、用户、公告、聊天等管理入口，不展示普通用户的购物车和结算流程。

### 3.2 管理端

管理端与用户端位于同一个小程序内，通过权限隔离展示不同界面，包含：

- 登录
- 仪表盘
- 菜单管理（分类、菜品、规格）
- 订单管理（确认、制作中、完成、取消）
- 用户管理（赠送虚拟货币、禁用）
- 公告管理（发布、编辑、上下架）
- 订单聊天（按订单回复用户，实时推送）
- 数据统计（可选）

## 4. 核心业务流程

### 4.1 用户点餐流程

1. 用户登录小程序。
2. 在“点菜” Tab 浏览分类和菜品。
3. 进入菜品详情，按需选择规格（如甜度、温度、加料、杯型）。
4. 将菜品加入购物车，可修改数量或重新选择规格。
5. 进入结算页，填写订单备注（不超过 100 字）。
6. 使用虚拟货币支付订单。
7. 订单支付成功后，等待管理员确认。

### 4.2 订单处理流程

1. 用户支付后，订单状态为“待支付”或“已支付”。
2. 管理员通过微信订阅消息收到新订单通知，在管理端查看订单。
3. 管理员确认订单后，订单进入“制作中”，并通知用户。
4. 餐品制作完成，管理员将订单置为“已完成”，用户收到完成通知。
5. 用户可随时取消订单，不设取消时限；已支付订单自动回补虚拟货币，取消操作同时通过微信订阅消息通知管理员。

### 4.3 虚拟货币赠送流程

1. 管理员在管理端选择用户。
2. 输入赠送金额并确认。
3. 用户余额增加，系统记录钱包流水。
4. 用户在“我的钱包”中看到余额和流水明细。

### 4.4 公告流程

1. 管理员在管理端发布或编辑公告。
2. 小程序首页顶部展示公告。
3. 管理员可将公告下线或重新启用。

### 4.5 订单聊天流程

1. 用户从订单详情或“聊天” Tab 进入会话。
2. 会话与订单绑定，仅支持文字消息。
3. 用户发送消息后，管理员实时收到新消息提示。
4. 管理员在管理端按订单查看并实时回复。
5. 双方在会话中可查看历史消息和发送时间。

## 5. 功能需求

### 5.1 登录

#### 5.1.1 用户登录

- 用户通过微信登录，自动注册或识别已有账号。
- 登录后保存登录状态，Token 过期后自动刷新。
- 登录成功进入“点菜”首页。

#### 5.1.2 管理员登录

- 管理员使用账号密码登录，独立于普通用户账号。
- 登录后在同一小程序内进入管理员界面。
- 用户端和管理员端通过权限隔离展示，普通用户不能访问管理入口。

### 5.2 菜品浏览与规格选择

- 菜品按分类展示，支持上下架和排序。
- 菜品详情展示基础价、描述、图片和规格组。
- 规格组包含多个规格项，规格项可设置加价金额。
- 菜品最终价格为基础价加所选规格项的加价之和。
- 下架或已删除菜品对用户端不可见，但历史订单不受影响。

### 5.3 购物车

- 购物车按用户隔离，保存在本地。
- 支持加入菜品、修改数量、删除菜品、清空购物车。
- 相同菜品和相同规格自动合并数量。
- 结算前校验菜品最新价格、上架状态和库存。
- 本地金额仅用于展示，实际金额以下单时服务端计算结果为准。

### 5.4 下单与虚拟货币支付

- 用户可填写订单备注，备注不超过 100 字。
- 下单时服务端重新计算金额，不信任客户端金额。
- 服务端校验菜品上架状态、库存和用户余额。
- 虚拟货币余额不足时整单失败，不做部分扣款。
- 支付成功后订单进入“已支付”状态，系统写入钱包流水。
- 相同订单幂等键不能重复创建订单或重复扣款。
- 用户取消订单不设时间限制；已支付订单取消后自动退回虚拟货币。
- 订单状态为：待支付 → 已支付 → 制作中 → 已完成；已支付订单可取消并自动退款。
- 管理员确认订单后，订单直接进入“制作中”，不新增独立确认状态。

### 5.5 订单与消息通知

#### 5.5.1 用户通知

- 用户下单成功后收到通知。
- 管理员确认订单后，订单直接进入“制作中”，用户收到制作中通知。
- 订单完成后，用户收到完成通知。
- 订单取消或退款后，用户收到退款通知。

#### 5.5.2 管理员通知

- 用户完成下单后，管理员通过微信订阅消息收到新订单通知。
- 用户取消订单后，管理员同样通过微信订阅消息收到取消通知。
- 通知内容至少包含订单号、用户和订单金额。
- 管理员需要在小程序内完成微信订阅授权，未授权时可在管理端订单列表中查看待处理订单。

### 5.6 聊天

- 聊天以订单为维度，一个订单对应一个会话。
- 用户和管理员可在会话中发送文字消息。
- 聊天仅支持文字，不支持图片和语音。
- 新消息实时推送，不依赖用户手动刷新。
- 消息展示发送者、发送时间和内容。
- 会话列表展示最近消息和未读数量。
- 用户可从订单详情或“聊天” Tab 进入会话。
- 管理员可从管理员端订单详情或会话列表进入聊天。

### 5.7 公告

- 管理员可发布公告，公告包含标题和正文。
- 管理员可编辑、启用或下线公告。
- 首页顶部展示当前启用的公告。
- 公告按发布时间倒序排列。

### 5.8 个人中心与钱包

- 用户可查看和修改个人资料。
- 用户可查看余额、钱包流水和订单记录。
- 钱包流水展示变动金额、变动后余额、类型和时间。
- 用户可查看公告和系统消息。

### 5.9 管理端（小程序内管理员界面）

#### 5.9.1 菜品管理

- 管理分类、菜品和规格。
- 设置菜品价格、库存、上下架状态和排序。
- 上传菜品图片。

#### 5.9.2 订单管理

- 查看订单列表和订单详情。
- 确认订单、标记制作中、标记完成。
- 取消订单并触发余额退款。

#### 5.9.3 用户管理

- 查看用户列表和用户详情。
- 给用户赠送虚拟货币。
- 禁用或启用用户。

#### 5.9.4 公告管理

- 发布、编辑、启用和下线公告。

#### 5.9.5 聊天管理

- 查看按订单归集的会话。
- 回复用户消息。

## 7. 业务规则

- 所有金额使用定点小数，禁止浮点运算。
- 下单金额由服务端重新计算，不信任客户端金额。
- 库存校验和扣减必须防止超卖。
- 余额扣减、订单创建和流水写入必须保证事务一致性。
- 余额不足、库存不足、菜品下架等情况必须给出明确提示。
- 订单备注支持中文和 emoji，数据库使用 `utf8mb4`。
- 默认管理员密码为临时密码，正式使用前必须修改。
- 微信订阅消息不可用时，订单状态改为轮询获取。
- 用户取消订单不设时限，取消后必须通知管理员。
- 聊天消息仅支持文字，并采用实时推送。

## 8. 非功能需求

- 适用规模为 5~10 人，以稳定可靠为主，不追求高并发。
- 用户下单、余额扣减和退款必须保证数据一致。
- 重复提交订单不能造成重复扣款。
- 管理端操作应实时反映到小程序端。
- 所有涉及金额、订单、库存的操作需要有流水或日志可追溯。
- 小程序端启动和主要页面切换应流畅。
- 聊天消息和公告需要持久化保存。
- 聊天消息需要实时送达，并支持断线后的重连或消息补偿。
- 管理员与用户界面必须按权限隔离，防止越权访问。
