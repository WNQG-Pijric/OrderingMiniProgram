# 07-notify：微信通知模块（订阅消息）

> 前置规则：`docs/prompts/00-project-rule.md`。依赖模块 05 order（状态变更事件）。

## 目标

订单状态变更时发送微信订阅消息通知。

## 模板

- 下单成功
- 订单完成
- 退款通知

## 接口

```
POST   /notify/send          # 服务端触发（内部调用，按事件分发）
```

小程序端引导：

```
wx.requestSubscribeMessage({ tmplIds: [...] })  # 下单前引导订阅
```

## 关键规则（硬性）

1. **一次性订阅**：微信订阅消息默认为一次性，下单前引导用户订阅对应模板。
2. **降级策略**：个人主体可申请的点餐类模板有限，申请不到时**降级为订单页轮询状态**（前端定时轮询订单状态，替代推送）。
3. 发送失败不影响订单主流程：通知模块异常仅记录日志，不阻断下单。
4. AppSecret 只存后端，openid 从订单 user 关联获取。
5. 触发点：订单支付成功 / 制作中 / 完成 / 取消退款后各发送一次对应模板。

## 输出物

- NotifyModule：发送服务 + 事件订阅（可用 NestJS EventEmitter 解耦）
- 小程序端订阅引导逻辑
- 订单页状态轮询兜底

## 验收标准

1. 状态变更正确触发对应模板发送。
2. 模板不可用时订单流程不受影响（降级轮询生效）。
