# 07-notify：微信通知模块（订阅消息）

> 前置规则：`docs/prompts/00-project-rule.md`。依赖模块 05 order（状态变更事件）。

## 目标

订单状态变更时向用户和管理员发送微信订阅消息通知。

## 模板

用户：

- 下单成功
- 制作中
- 订单完成
- 退款通知

管理员：

- 新订单通知
- 订单取消通知

## 接口

```
POST   /notify/send          # 服务端触发（内部调用，按事件分发）
```

小程序端引导：

```
wx.requestSubscribeMessage({ tmplIds: [...] })  # 下单前引导订阅
```

管理员端引导：

```
wx.requestSubscribeMessage({ tmplIds: [...] })  # 管理员在小程序内完成订阅授权
```

## 关键规则（硬性）

1. **一次性订阅**：微信订阅消息默认为一次性，下单前引导用户订阅对应模板；管理员也需在小程序内订阅管理员模板。
2. **降级策略**：个人主体可申请的点餐类模板有限，申请不到时**降级为订单页轮询状态**（前端定时轮询订单状态，替代推送）。
3. 发送失败不影响订单主流程：通知模块异常仅记录日志，不阻断下单。
4. AppSecret 只存后端；用户 openid 从订单 user 关联获取，管理员 openid 从 `admin.wechat_openid` 获取（绑定见模块 10 的 `POST /admin/auth/bind-openid`）。
5. 触发点：订单支付成功 / 制作中 / 完成 / 取消退款后向用户发送；新订单 / 取消订单后向管理员发送。

## 输出物

- NotifyModule：发送服务 + 事件订阅（可用 NestJS EventEmitter 解耦）
- 小程序端订阅引导逻辑
- 管理员端订阅引导逻辑
- 订单页状态轮询兜底

## 验收标准

1. 状态变更正确触发对应模板发送。
2. 用户新订单、订单完成、退款通知发送成功。
3. 管理员新订单、取消订单通知发送成功。
4. 模板不可用时订单流程不受影响（降级轮询生效）。
