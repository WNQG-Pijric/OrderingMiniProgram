# 06-wallet：钱包模块（余额支付 / 退款回补 / 流水）

> 前置规则：`docs/prompts/00-project-rule.md`。依赖模块 00 schema、05 order。
>
> 涉及金额、并发，本项目**安全底线最高的模块**。

## 目标

余额支付、退款回补、流水记录；充值方式为管理员后台赠送（见模块 08）。

## 数据表

- user.balance
- wallet_log

## 流程

- **支付**：下单 → 服务端重算 → 行锁扣余额 → 写流水（`type=pay`）→ 订单置为已支付，**同一事务**。
- **退款**：取消已支付订单 → 行锁回补余额 → 写流水（`type=refund`）→ 订单置为已取消，**同一事务**。
- **赠送**：管理员后台赠送 → 写流水（`type=gift`）→ 余额增加。

## 关键规则（硬性）

1. **并发控制**：扣款 / 回补使用 `SELECT ... FOR UPDATE` 行锁（Prisma `$queryRaw` 或 `$transaction` 内显式行锁），禁止「读-算-写」非原子操作。
2. **余额不足**：返回 `40001`，**不做部分扣款**（整单失败）。
3. **事务一致性**：下单 + 扣款 + 流水（pay）必须同一事务，任一步失败整体回滚。
4. **快照**：wallet_log 记录 `change` 与 `balance_after`（变动后余额），便于对账。
5. **幂等**：支付操作由订单状态守卫（待支付才能支付）+ `client_order_no` 防重，禁止重复扣款。
6. 金额运算用 Prisma `Decimal`，禁止浮点。

## 输出物

- WalletService（提供 `pay` / `refund` / `gift` / `listLogs`，供 order、admin 模块调用）
- 与模块 05 订单创建流程集成（创建订单即支付）
- Swagger 注解、单元测试 + **并发测试用例**（并发扣款、退款回补）

## 验收标准

1. 并发两笔支付，余额最终一致（不出现超扣）。
2. 余额不足整单失败，返回 `40001`，订单不落库或回滚。
3. 每笔变动有流水，`balance_after` 连续可对账。
4. 退款回补后余额精确恢复，不重复回补。
