# 10-test：整体测试与联调

> 前置规则：`docs/prompts/00-project-rule.md`。全部业务模块完成后的收尾模块。

## 目标

端到端回归测试、并发 / 幂等专项验证、边界场景补测，确保全链路可用。

## 覆盖范围

### 全链路用例

1. 注册登录 → 浏览菜单 → 加购 → 下单 → 支付 → 管理员标记制作中 / 完成 → 订单页看到完成状态。
2. 余额不足下单 → 返回 `40001`，订单不落库。
3. 取消已支付订单 → 余额回补 + 流水（refund）+ 状态已取消。
4. 管理员赠送余额 → 余额增加 + 流水（gift）。
5. 禁用用户 → 无法登录 / 下单（`20004`）。

### 并发 / 幂等专项（必测）

| 场景 | 预期 |
|---|---|
| 相同 `client_order_no` 并发提交 | 只创建一个订单，只扣一次款 |
| 并发下单扣库存 | 不超卖 |
| 并发扣余额（余额恰好足够一笔） | 一笔成功、一笔 `40001`，余额不为负 |
| 重复取消已支付订单 | 只退款一次 |
| 并发赠送 + 消费 | 余额最终一致 |

### 边界场景

- 库存为 0 / 菜品下架后加购下单
- 备注含 emoji（utf8mb4 落库）
- 规格加价金额累加正确性
- 订单快照在菜品改名 / 删品后仍正确

## 工具

- 后端：Jest + Supertest（集成测试）、`@nestjs/testing`
- 数据库：测试库（独立 schema），`prisma migrate reset` + seed 初始化
- 前端：小程序开发者工具真机调试、后台浏览器 E2E（Playwright 可选）

## 验收标准

1. 核心用例全部通过，并发 / 幂等专项无失败。
2. 修复所有回归问题，代码合并至 main。
3. 补充测试通过后才进入部署联调（README「十六」）。
